大数据架构设计和未来发展研究

我是一个汽车公司，研发体系的大数据部门架构设计师。
当前我掌握的大数据架构和基础情况如下。、

1.中国国内采用混合云架构，公有云使用华为云，私有云在公司服务器机房部署有cdp7.9.2
华为云公有云介绍：
1）云上主要使用如下几个产品：
TCP接入服务（集群形势，有20多台虚拟机，主要和车端通讯，采集国标32960要求的国标数据）。
数据缓存kafka服务(有7个kafka集群，56台服务器，包含之前说的国标，还有企业自己定义的企标（几年前的车型只能发30秒频率的数据，车辆硬件限制），企标1秒（近几年的稍微低端的车型发1秒频率的数据），高精度数据（近几年的稍高端的车型最高发100毫秒频率的数据，大部分信号也是1秒的新增部分信号可发100毫秒，在车端将所有数据1分钟打包一包发给云端），国标扩展数据（部分的车辆，根据需求配置的发1秒频率的数据，是在国企标之外定义的可以灵活更新信号采集的一种数据，方便临时事件要求的数据业务，可快速下方更新采集，云端快速处理，在车端将所有数据10秒的数据打包一包发给云端），BMS数据（部分的车辆，根据需求配置的发1秒频率的数据，主要上传关于电池的数据，专用于电池安全业务），充电桩的数据（充电桩上传到云端的数据）)，这些kafka分为不同的集群，避免相互影响，采用kafka 3 的版本，数据写在本地服务器上，一般可保存20-72小时，利用率通常在50-60%，节假日用车高峰时有性能瓶颈，需要重点关注。
日志采集服务（这是一个华为云MRS集群，在上面构建了28台服务器的hadoop集群，主要运行spark streaming任务。设计逻辑时每2分钟采集一次kafka数据，使用车架号后3位进行shuffle,写入到华为云OBS对象存储文件目录，按照小时级目录份文件，每一小时文件写完，私有云会启动一个拉取数据的任务将上一个小时的文件夹下所有数据拉到云下，进行长期存储，云上小时级的2分钟切片的文件在对象存储值保留7天，作为环冲，避免因为云上云下专线问问题，数据堆积，当前spark streaming方案已有性能瓶颈，在测试使用flink接收kafka数据）
